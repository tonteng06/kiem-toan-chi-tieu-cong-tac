# Progress 2026-10-17 - TV2

## Done
- Restored the manual agent loop that PR #5 had replaced (`run_agent`, `MAX_STEPS`, `parse_action`, `RegistryToolbox`), so `tests/test_agent.py` imports and passes again (TV1's final regression note flagged this blocker).
- Added the write tool `submit_decision(claim_id, decision, reason)` to the registry. Only APPROVED / REJECTED / ESCALATED / NEED_MORE_INFO can be written; `NO_ANSWER` is never persisted; transitions are checked by the state store.
- Added `src/agent/evidence_gate.py`. The write is refused (observation `Error: ...`, nothing written) unless: `calculate_claim` ran for that claim, the decision equals the rule engine's recommended status, and every policy reference cited by the calculation (e.g. `DOC003@v1.0`) appeared in a `search_policy` result. No usable policy evidence -> the agent must answer `NO_ANSWER`.
- After every successful write the loop itself calls `get_claim_status` and compares the persisted status with the expected one: `VERIFY SUCCESS` / `VERIFY FAILED` (the run stops with `verify_failed` and `NO_ANSWER` on a mismatch). A final decision on a claim is only accepted after a verified write of that same decision.
- `src/agent/llm_client.py`: `call_llm` for Groq (OpenAI-compatible endpoint), standard library only. Timeout, retry with backoff on timeouts / connection errors / 408 / 429 / 5xx, no retry on other 4xx or a missing key, HTTP errors logged (key never logged). There is no fallback to a fake model: without `GROQ_API_KEY` or after a failure it raises and the run ends as `llm_error`.
- Fixes found during the first real run: `urllib_transport` now sends a `User-Agent` header (Cloudflare rejected the default `Python-urllib` agent with HTTP 403, code 1010), and on HTTP 429 the retry waits at least the server's "try again in Ns" hint (capped at 60 s) instead of only 1 s, 2 s, 4 s.
- Usage is returned per model call and summed per question by `run_agent`: `calls`, `prompt_tokens`, `completion_tokens`, `max_prompt` (the names TV1's contract requires). `run_log.py` writes one JSONL record per question (timestamp, steps, tool args/results, verified write, usage).
- `scripts/demo_agent.py`: runs the real LLM agent on sample claims against a temporary copy of the claims file and appends to a log. It reads `GROQ_API_KEY` (and optionally `GROQ_MODEL`) from the environment or a `.env` file.

## Problem
- Blockers hit on the first real run, all solved without changing the agent protocol:
  - HTTP 403 (code 1010) from Cloudflare: the default `Python-urllib` User-Agent was rejected. Fixed by sending our own `User-Agent`.
  - HTTP 404 `model_not_found` for `llama-3.3-70b-versatile` and `llama-3.1-8b-instant`: the `GET /models` call for our key lists no Llama chat model. The real run uses `qwen/qwen3.8-27b` instead. It is a Groq preview model that can be discontinued at short notice.
  - HTTP 400 (`tool_use_failed`, `json_validate_failed`) with `openai/gpt-oss-120b`: that model tries native tool calling, which conflicts with our JSON-action protocol written in the prompt. Not used.
  - HTTP 429 on input tokens per minute (limit 7000 on the free tier): fixed by honoring the server's retry hint; a 4-claim run takes about 12 minutes.
- Three real logs exist (`agent_run_01`, `02`, `03`), but runs 02 and 03 repeat claims from run 01 with identical token counts (`temperature=0`). There is no real faithfulness / decision-accuracy number from TV2 yet (handed to TV1).
- `submit_decision` exists twice: the registry one (used by `run_agent` with `RegistryToolbox`) and TV3's MCP write tool. Both use `StateStore`; running the agent through `McpToolbox` needs TV3's tool to take `claim_id, decision, reason` like the registry one.
- `GROQ_API_KEY=` and `GROQ_MODEL=qwen/qwen3.8-27b` should be added to `.env.example` (TV3's file), without a real key.
