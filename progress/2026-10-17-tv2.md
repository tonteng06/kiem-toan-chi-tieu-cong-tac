# Progress 2026-10-17 - TV2

## Done
- Restored the manual agent loop that PR #5 had replaced (`run_agent`, `MAX_STEPS`, `parse_action`, `RegistryToolbox`), so `tests/test_agent.py` imports and passes again (TV1's final regression note flagged this blocker).
- Added the write tool `submit_decision(claim_id, decision, reason)` to the registry. Only APPROVED / REJECTED / ESCALATED / NEED_MORE_INFO can be written; `NO_ANSWER` is never persisted; transitions are checked by the state store.
- Added `src/agent/evidence_gate.py`. The write is refused (observation `Error: ...`, nothing written) unless: `calculate_claim` ran for that claim, the decision equals the rule engine's recommended status, and every policy reference cited by the calculation (e.g. `DOC003@v1.0`) appeared in a `search_policy` result. No usable policy evidence -> the agent must answer `NO_ANSWER`.
- After every successful write the loop itself calls `get_claim_status` and compares the persisted status with the expected one: `VERIFY SUCCESS` / `VERIFY FAILED` (the run stops with `verify_failed` and `NO_ANSWER` on a mismatch). A final decision on a claim is only accepted after a verified write of that same decision.
- `src/agent/llm_client.py`: `call_llm` for Groq (OpenAI-compatible endpoint), standard library only. Timeout, retry with backoff on timeouts / connection errors / 408 / 429 / 5xx, no retry on other 4xx or a missing key, HTTP errors logged (key never logged). There is no fallback to a fake model: without `GROQ_API_KEY` or after a failure it raises and the run ends as `llm_error`.
- Usage is returned per model call and summed per question by `run_agent`: `calls`, `prompt_tokens`, `completion_tokens`, `max_prompt` (the names TV1's contract requires). `run_log.py` writes one JSONL record per question (timestamp, steps, tool args/results, verified write, usage).
- `scripts/demo_agent.py`: runs the real LLM agent on sample claims against a temporary copy of the claims file and appends to a log.
- One system prompt in `src/agent/prompts/agent_system.txt` (the two conflicting prompts concatenated by PR #5 are now a single JSON-action protocol that mentions `submit_decision`).
