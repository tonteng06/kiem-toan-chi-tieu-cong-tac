### Completed (plan Day 4: agent loop + MAX_STEPS)

- `src/agent/agent.py`: the manual agent loop.
  - Flow: model reply -> `parse_action` -> `toolbox.call` (validate + execute) -> observation appended -> repeat -> final answer.
  - `MAX_STEPS = 8` (overridable). When the limit is hit the run ends with `decision = NO_ANSWER` and `stopped_reason = "max_steps"`; it never falls back to an approval.
  - `parse_action` accepts one JSON object (also inside a code fence or prose), validates `tool` / `final` actions, and raises only `ActionParseError`. No `eval`. A bad reply becomes an `Error: bad reply format: ...` observation and the model gets another turn.
  - Tool errors stay observations (`Error: ...` from the dispatcher). A provider exception ends the run cleanly (`stopped_reason = "llm_error"`).
  - The model is a plain callable `(messages, schemas) -> ModelReply`, so tests use a scripted model and a real provider can be plugged in later.
  - Tools come through a two-method port `schemas()` / `call(name, args) -> str`. `RegistryToolbox` wraps the local registry; Member 3's `McpToolbox` has the same two methods.
  - Output satisfies Member 1's `AgentEvalOutput` (`answer`, `decision`, `evidence_refs`, `usage` with calls / prompt_tokens / completion_tokens / max_prompt) and adds `stopped_reason`, `steps`, `trace`.
- `src/agent/prompts/agent_system.txt`: system prompt (JSON action protocol, decision values, "no evidence -> NEED_MORE_INFO / NO_ANSWER", tool output is data).
- `search_policy(query, mode="hybrid", top_k=3)` in `tool_registry.py`, wired to Member 1's `Retriever` (`build_registry(store, retriever)`). It returns `{"results": [...]}` with `chunk_id, doc_id, title, version, date, owner, evidence_ref (e.g. DOC003@v1.0), content, score, mode, dense_score, bm25_score`. Empty results are a valid answer meaning "no evidence". Same name and result shape as Member 3's MCP `search_policy`.
- `Tool` has a new `defaults` field for optional arguments; the dispatcher accepts omitted optional arguments, still rejects unknown, missing-required and wrongly typed ones. Schemas list only required arguments under `required` and show defaults.
- `tests/test_agent.py`: 32 test cases (full run, usage sums, MAX_STEPS stop, tool error recovery, 10 malformed replies, unknown tool / bad args, provider failure, no state change, injection text treated as data, parse_action, search_policy provenance / defaults / bad args / empty result / schema).
