DAY 3 - CLAIM-TO-POLICY GROUNDING ANALYSIS

1. Purpose

Day 3 integrates Member 1's RAG Retriever with Member 2's claim and business-rule layer.

The goal of this evaluation is to verify whether each policy issue detected by the deterministic business rules can be grounded in the correct policy document and version retrieved by the RAG system.

This is a grounding evaluation, not an LLM faithfulness evaluation. Faithfulness requires a generated Agent answer and will be evaluated after the Agent output interface is available.

2. Integrated components

Member 1:
- Policy corpus
- Document and Chunk models
- Dense retrieval
- Hybrid BM25 + Dense retrieval
- Retriever facade

Member 2:
- Claim and Expense models
- Claim status transitions
- JSON StateStore
- Deterministic calculate_claim business rules

The original Member 1 RAG implementation was not modified during this integration.

3. Evaluation method

Each sample claim is passed through:

calculate_claim(claim)

The business-rule output contains:
- violations
- missing_data
- recommended_status
- evidence reference such as DOC003@v1.0

For every violation or missing-data issue, the issue message is used as a retrieval query.

Both Dense and Hybrid retrieval are evaluated with Top-3 unique document/version references.

An issue is counted as grounded when its expected evidence reference appears in the retrieved Top-3.

Example:

CLM-002
HOTEL_OVER_LIMIT
Expected evidence: DOC003@v1.0

Hybrid retrieved:
1. DOC003@v1.0
2. DOC004@v1.0
3. DOC008@v1.0

Therefore this issue is grounded.

5. Results

Dense:
- Total issues: 5
- Grounded issues: 5
- Grounding@3: 100%

Hybrid:
- Total issues: 5
- Grounded issues: 5
- Grounding@3: 100%

All five issue-level policy references were retrieved successfully in both Dense and Hybrid modes.

The evaluation checks both document ID and policy version, for example DOC002@v2.0 rather than only DOC002.

6. Important distinction from Day 1 and Day 2

Day 1:
Evaluated question-to-policy retrieval using Hit@3 and Recall@3.

Day 2:
Analyzed Dense, BM25 and Hybrid component scores for Q13, Q14 and Q15.

Day 3:
Evaluates whether issues produced by the claim business-rule layer can be grounded back to the expected policy document and version through the RAG Retriever.

Therefore Day 3 connects the claim/business-rule layer with the RAG layer instead of evaluating them independently.

7. Limitations

Grounding@3 is not the same as answer faithfulness.

The current evaluation does not yet measure:
- LLM answer faithfulness
- correct refusal rate from Agent answers
- token usage
- LLM call count
- prompt token count
- completion token count
- max prompt size

These metrics require the end-to-end Agent output and usage interface from the Agent layer.

The business rules also mirror several policy values as deterministic constants. This is useful for calculation and testing, but the final Agent must still use retrieved policy evidence for grounding.

Ground Transportation Policy coverage is not yet complete in calculate_claim. Receipt requirements are checked, but all transportation-specific policy rules are not represented in the current deterministic business rules.

9. Conclusion

The Day 3 integration confirms that Member 2's current deterministic policy issues are compatible with Member 1's RAG pipeline.

For all five evaluated policy issues, both Dense and Hybrid retrieval returned the expected document and version within the Top-3.

Current result:
Dense Grounding@3 = 100%
Hybrid Grounding@3 = 100%

The next end-to-end evaluation stage will require actual Agent-generated answers in order to measure faithfulness, correct refusal and token usage.
